MAVULA enforces a maker-checker control on all account lifecycle transitions. An `operations_maker` submits a transition request, which is held in `PENDING_APPROVAL` state until a separate `operations_checker` either approves or rejects it. The same principal cannot approve a request they submitted — doing so returns a `403`. This separation of duties applies to all three transitions: `FREEZE`, `UNFREEZE`, and `CLOSE`.

## Role matrix

| Role | Permitted actions |
|---|---|
| `operations_maker` | Create accounts · Submit lifecycle requests · Read own requests |
| `operations_checker` | Review pending requests · Approve or reject requests · Read all requests |

<Steps>

### Submit a transition request

Call `POST /api/accounts/{accountId}/status-transitions` using a maker token. Supply the `transition` (one of `FREEZE`, `UNFREEZE`, or `CLOSE`) and a human-readable `reason`. Include a fresh `Idempotency-Key` so the request is safe to retry on network failure.

<CodeGroup>

```bash curl
curl -sS -X POST https://ledger.mavula.dev/api/accounts/ACCOUNT_ID/status-transitions \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f2b1e3a-4c2d-4d63-9b1a-2f7b6c0d5e91" \
  -H "X-Correlation-ID: 0f3c8d7a-6e1b-4a98-8d7f-9c1a2b3d4e5f" \
  -d '{"transition": "FREEZE", "reason": "Suspected fraud"}'
```

```go Go
package main

import (
    "net/http"
    "strings"

    "github.com/google/uuid"
)

func submitFreeze(ledgerURL, accountID, makerToken string) (*http.Response, error) {
    body := strings.NewReader(`{"transition":"FREEZE","reason":"Suspected fraud"}`)
    req, err := http.NewRequest(http.MethodPost,
        ledgerURL+"/api/accounts/"+accountID+"/status-transitions", body)
    if err != nil {
        return nil, err
    }
    req.Header.Set("Authorization", "Bearer "+makerToken)
    req.Header.Set("Content-Type", "application/json")
    req.Header.Set("Idempotency-Key", uuid.NewString())
    req.Header.Set("X-Correlation-ID", uuid.NewString())
    return http.DefaultClient.Do(req)
}
```

### Approve or reject the request

A **different** operator — one holding the `operations_checker` role — approves the request by calling `POST /api/account-lifecycle-requests/{requestId}/approve`. If the evidence is insufficient, the checker calls `/reject` instead, supplying a mandatory reason.

<CodeGroup>

```bash curl (approve)
curl -sS -X POST https://ledger.mavula.dev/api/account-lifecycle-requests/REQUEST_ID/approve \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: a65e192f-aa5f-4dc9-a111-baf6136595a0" \
  -d '{"reason": "Evidence reviewed and confirmed"}'
```

```bash curl (reject)
curl -sS -X POST https://ledger.mavula.dev/api/account-lifecycle-requests/REQUEST_ID/reject \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: c87b240e-f31a-4ae1-b998-3e12f7d09001" \
  -d '{"reason": "Insufficient evidence — request resubmission with supporting documentation"}'
```

func decideRequest(ledgerURL, requestID, checkerToken, decision, reason string) (*http.Response, error) {
    body := strings.NewReader(`{"reason":"` + reason + `"}`)
    req, err := http.NewRequest(http.MethodPost,
        ledgerURL+"/api/account-lifecycle-requests/"+requestID+"/"+decision, body)

    req.Header.Set("Content-Type", "application/json")

    return http.DefaultClient.Do(req)
}
// decision = "approve" or "reject"

### Verify the applied state

After the checker acts, read the request and then the account to confirm the transition was applied. The request `status` moves from `PENDING_APPROVAL` to `APPLIED` on success, or to `REJECTED` or `FAILED` otherwise.

```bash
# Read the lifecycle request
curl -sS https://ledger.mavula.dev/api/account-lifecycle-requests/REQUEST_ID \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"

# Confirm the account's new status
curl -sS https://ledger.mavula.dev/api/accounts/ACCOUNT_ID \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```

</Steps>

<Warning>
  **Self-approval is rejected.** The maker and checker must be distinct effective operators. If the principal who submitted the request attempts to approve it, the API returns `403 Forbidden`. Ensure your integration uses separate credentials for each role.
</Warning>

## Error reference

| HTTP status | Meaning | Resolution |
|---|---|---|
| `400` | Invalid transition or malformed body | Validate the `transition` value and `reason` field |
| `403` | Missing permission or self-approval attempted | Use a distinct checker account that holds `finance.approve` |
| `404` | Account or request not found in the tenant | Verify identifiers and that you are operating in the correct tenant |
| `409` | Idempotency or state conflict | Reuse the key only for an identical retry; refresh current state before retrying |
