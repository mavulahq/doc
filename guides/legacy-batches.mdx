Workbench orchestrates two distinct batch workflows: regulatory exports and legacy import validation. A regulatory export produces a signed artifact of transaction history for a given period, records its delivery to a supervisory authority, and retains a durable receipt for audit purposes. A legacy import validates a file of historical records for structural correctness without creating any financial mutations in the ledger. Both workflows produce a `LegacyBatchReceipt` that persists across worker retries and process restarts - record the batch `id` as soon as you receive it.

<Warning>
  **Legacy import does NOT create financial mutations.** Validation acceptance - even a fully clean import with zero rejections - does not post transactions, create accounts, or alter ledger balances in Ledger Core. A separate, explicitly approved migration process is required for any financial effects. Never assume that a `VALIDATED` batch state means your data has been applied to live accounts.
</Warning>

## Recovery guidance

If your client did not receive a response (network timeout, connection drop), **do not create a second export or import**. Instead:

1. **List existing batches** using `GET https://workbench.mavula.dev/api/legacy-batches` to locate your batch by approximate creation time or correlation ID.
2. **Read the specific batch** once you have identified its `id`.
3. **Retry a timed-out submission** only if no matching batch exists - and in that case, reuse the **original `Idempotency-Key`** with the **identical payload**. Using a different key for the same logical request creates a duplicate batch.

<Tip>
  Always log your `Idempotency-Key` and `X-Correlation-ID` before sending a batch request. These two values are your primary recovery tools if a response is lost.
</Tip>
