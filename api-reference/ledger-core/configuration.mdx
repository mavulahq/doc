The Configuration API is the institutional setup layer of the Ledger Core platform. You use it to define the financial products that accounts are created against, the eligibility and behavioural rules that govern those products, the entity schemas that describe your business objects, and the automated workflows that respond to financial events. Configuration mutations require the `configuration.write` permission, while all read operations require `finance.read`.

---

## Products

Products are the templates that govern account behaviour — they define currency, minimum balance rules, applicable fee structures, and more. Every account is associated with exactly one product at creation time.

### Endpoint summary

| Method | Path | Permission | Description |
|---|---|---|---|
| `GET` | `/api/products` | `finance.read` | List all financial products for the tenant. |
| `POST` | `/api/products` | `configuration.write` | Create or update a financial product. |
| `GET` | `/api/products/config` | `finance.read` | Read the tenant-level product configuration. |
| `POST` | `/api/products/config/generate` | `configuration.write` | Generate jurisdiction-specific product defaults. |
| `GET` | `/api/products/{productId}` | `finance.read` | Read a single financial product. |

### Create or update a financial product

<Note>
  **Required permission:** `configuration.write` — Requires `Idempotency-Key` header.
</Note>

Creates a new product or updates an existing one. This is an upsert operation; the product `id` in the request body determines whether a new record is created or an existing one is overwritten.

```
POST https://ledger.mavula.dev/api/products
```

### Request body

<ParamField body="type" type="string" required>
  Product type identifier, e.g. `SAVINGS`, `CURRENT`, `LOAN`. Max 128 chars.
</ParamField>

<ParamField body="config" type="object" required>
  Product-specific configuration as a free-form object. The schema depends on the product type.
</ParamField>

<CodeGroup>
```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/products \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: c87f312a-1b2c-4e5d-9f8a-7b6c5d4e3f2a" \
  -H "X-Correlation-ID: d98g423b-2c3d-5f6e-0g9b-8c7d6e5f4g3b" \
  -d '{
    "type": "SAVINGS",
    "config": {
      "currency": "MZN",
      "minimum_balance": "0.00",
      "interest_rate": "0.0350"
    }
  }'
```
</CodeGroup>

**Response `201`** — Returns the stored `Product` object.

## Rules

Rules define the conditions and actions that govern product behaviour — for example, eligibility criteria, spending limits, or fee triggers. Each rule belongs to exactly one product.

### Endpoint summary

| Method | Path | Permission | Description |
|---|---|---|---|
| `GET` | `/api/products/{productId}/rules` | `finance.read` | List all rules for a product. |
| `POST` | `/api/products/{productId}/rules` | `configuration.write` | Create a rule for a product. |
| `POST` | `/api/products/{productId}/rules/defaults` | `configuration.write` | Seed the default rule set for a product. |
| `PUT` | `/api/products/{productId}/rules/{ruleId}` | `configuration.write` | Update a product rule. |
| `DELETE` | `/api/products/{productId}/rules/{ruleId}` | `configuration.write` | Delete a product rule. |

## Schemas

Schemas let you define the structure of the custom entities your institution works with — for example, business registration records, KYC documents, or collateral descriptions. Each schema is a named collection of typed field definitions.

### Endpoint summary

| Method | Path | Permission | Description |
|---|---|---|---|
| `GET` | `/api/schemas` | `finance.read` | List all entity schemas for the tenant. |
| `POST` | `/api/schemas` | `configuration.write` | Create an entity schema. |
| `POST` | `/api/schemas/import` | `configuration.write` | Import an entity schema from a portable definition. |
| `POST` | `/api/schemas/presets/business-registration` | `configuration.write` | Create the built-in business registration schema. |
| `GET` | `/api/schemas/{schemaId}` | `finance.read` | Read a single entity schema. |
| `GET` | `/api/schemas/{schemaId}/export` | `finance.read` | Export a schema as a portable definition. |

    <ParamField body="description" type="string">Human-readable field description.</ParamField>
  </Expandable>

<CodeGroup>
```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/schemas \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: m87p312k-1l2m-4o5n-9p8k-7l6m5n4o3p2k" \
```

## Workflows

Workflows are configurable automation definitions that execute a series of steps when a financial event occurs. You can use them to send notifications, charge fees, update records, or chain any sequence of actions in response to a trigger event.

| `GET` | `/api/workflows/trigger/{trigger}` | `finance.read` | List workflows bound to a specific trigger. |
| `POST` | `/api/workflows/presets/loan-approval-notification` | `configuration.write` | Create the loan approval notification preset. |
| `POST` | `/api/workflows/presets/monthly-fee-charge` | `configuration.write` | Create the monthly fee charge preset. |
| `GET` | `/api/workflows/{workflowId}` | `finance.read` | Read a single workflow. |
| `POST` | `/api/workflows/{workflowId}/execute` | `finance.write` | Execute a workflow manually. |
