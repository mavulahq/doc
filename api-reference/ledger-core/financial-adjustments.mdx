---

The Financial Adjustments API lets you correct the financial record without editing history in place. When a transaction or journal entry has been posted in error, you submit a `REVERSAL` or `CORRECTION` request against it. The original record remains immutable - the adjustment produces new, offsetting entries only after a separate operator approves the request. This keeps your audit trail complete and your controls intact.

<Note>
  **Maker-checker rule:** The principal who submits an adjustment request (`finance.write`) and the principal who approves or rejects it (`finance.approve`) must be distinct operators. Self-approval returns `403 Forbidden`.
</Note>

---

## Submit a financial adjustment request

<Note>
  **Required permission:** `finance.write` - Requires `Idempotency-Key` header.
</Note>

Submits a `REVERSAL` or `CORRECTION` against a posted `TRANSACTION` or `JOURNAL_ENTRY`. The request is created in `PENDING_APPROVAL` status and must be reviewed by a different operator before any financial effect is applied.

```text
POST https://ledger.mavula.dev/api/financial-adjustment-requests
```

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.write` permission.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this operation (16–128 chars, `[A-Za-z0-9._:-]+`).
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier. Recommended for log correlation.
</ParamField>

### Request body

<ParamField body="target_type" type="string" required>
  The type of record to adjust. One of `TRANSACTION` or `JOURNAL_ENTRY`.
</ParamField>

<ParamField body="target_id" type="string" required>
  The identifier of the target transaction or journal entry. Max 128 chars.
</ParamField>

<ParamField body="adjustment_type" type="string" required>
  The kind of adjustment. `REVERSAL` fully offsets the original; `CORRECTION` reverses the original and posts a replacement.
</ParamField>

<ParamField body="reason" type="string" required>
  Human-readable explanation. Min 1 char, max 500 chars.
</ParamField>

<ParamField body="correction" type="object">
  Required when `adjustment_type` is `CORRECTION`. Defines the replacement financial effect.

  <Expandable title="correction fields">
    <ParamField body="correction.lending" type="object">
      Lending allocation for loan-related corrections.

      <Expandable title="lending fields">
        <ParamField body="correction.lending.amount" type="string" required>
          Corrected amount as a decimal string.
        </ParamField>

        <ParamField body="correction.lending.currency" type="string" required>
          ISO 4217 currency code.
        </ParamField>

        <ParamField body="correction.lending.allocation" type="object">
          Breakdown of the correction amount.

          <Expandable title="allocation fields">
          </Expandable>
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="correction.journal" type="object">
      Double-entry journal lines for the replacement posting.

      <Expandable title="journal fields">
        <ParamField body="correction.journal.ledger_lines" type="array" required>
          At least two ledger lines, each with an `account_code` and either `debit_amount` or `credit_amount`.
        </ParamField>

        <ParamField body="correction.journal.account_postings" type="array">
          Optional account-level postings to accompany the ledger lines.
        </ParamField>
      </Expandable>
    </ParamField>
  </Expandable>
</ParamField>

<CodeGroup>

```bash Reversal
curl -sS -X POST https://ledger.mavula.dev/api/financial-adjustment-requests \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7b0491f2-eb4c-42b2-b77d-acadd27c571b" \
  -H "X-Correlation-ID: 2d94d70b-77fa-4a58-af9f-d49c6849632f" \
  -d '{
    "target_type": "TRANSACTION",
    "target_id": "transaction_001",
    "adjustment_type": "REVERSAL",
    "reason": "Duplicate posting"
  }'
```

```bash Correction (journal)
curl -sS -X POST https://ledger.mavula.dev/api/financial-adjustment-requests \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 8c1502g3-fc5d-53c3-c88e-bcbee38d682c" \
  -H "X-Correlation-ID: 3e05e81c-88gb-5b69-bg0g-e5e7cbae743g" \
  -d '{
    "target_type": "JOURNAL_ENTRY",
    "target_id": "journal_001",
    "adjustment_type": "CORRECTION",
    "reason": "Correct clearing account code",
    "correction": {
      "journal": {
        "ledger_lines": [
          {"account_code": "1100", "debit_amount": "100.00"},
          {"account_code": "2100", "credit_amount": "100.00"}
        ]
      }
    }
  }'
```

</CodeGroup>

<Warning>
  Never retry a `CORRECTION` request with changed `correction` lines under the same `Idempotency-Key`. Change the key or resolve the conflict before resubmitting.
</Warning>

### Response `201`

Returns the created `FinancialAdjustmentRequest` with `status: "PENDING_APPROVAL"`.

```json
{
  "id": "adjreq_x5y4z3w2",
  "target_type": "TRANSACTION",
  "target_id": "transaction_001",
  "adjustment_type": "REVERSAL",
  "reason": "Duplicate posting",
  "status": "PENDING_APPROVAL",
  "requested_by": "operator_maker_01",
  "correlation_id": "2d94d70b-77fa-4a58-af9f-d49c6849632f",
  "created_at": "2024-11-15T11:00:00.000Z"
}
```

## List financial adjustment requests

<Note>
  **Required permission:** `finance.read`
</Note>

Returns a cursor-paginated list of adjustment requests. You can filter by status, adjustment type, or the target record.

```text
GET https://ledger.mavula.dev/api/financial-adjustment-requests
```

### Query parameters

<ParamField query="status" type="string">
  Filter by request status: `PENDING_APPROVAL`, `APPLIED`, `REJECTED`, or `FAILED`.
</ParamField>

<ParamField query="adjustment_type" type="string">
  Filter by type: `REVERSAL` or `CORRECTION`.
</ParamField>

<ParamField query="target_type" type="string">
  Filter by target record type: `TRANSACTION` or `JOURNAL_ENTRY`.
</ParamField>

<ParamField query="target_id" type="string">
  Filter to requests targeting a specific record identifier.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor from a previous response's `next_cursor`.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results per page. Min `1`, max `100`, default `50`.
</ParamField>

<CodeGroup>

```bash List pending reversals
curl -sS 'https://ledger.mavula.dev/api/financial-adjustment-requests?status=PENDING_APPROVAL&adjustment_type=REVERSAL' \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```

```bash Filter by target record
curl -sS 'https://ledger.mavula.dev/api/financial-adjustment-requests?target_id=transaction_001' \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```

</CodeGroup>

### Response `200`

<ResponseField name="items" type="array" required>
  Array of `FinancialAdjustmentRequest` objects.
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Opaque cursor for the next page. Absent when no further results exist.
</ResponseField>

## Read a financial adjustment request

<Note>
  **Required permission:** `finance.read`
</Note>

Returns a single adjustment request by its identifier. Poll this endpoint to confirm when an approved request has been `APPLIED` or has entered `FAILED` status.

```text
GET https://ledger.mavula.dev/api/financial-adjustment-requests/{requestId}
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique adjustment request identifier.
</ParamField>

<CodeGroup>

```bash cURL
curl -sS https://ledger.mavula.dev/api/financial-adjustment-requests/adjreq_x5y4z3w2 \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```

</CodeGroup>

### Response `200`

<ResponseField name="id" type="string" required>
  Unique request identifier.
</ResponseField>

<ResponseField name="target_type" type="string" required>
  `TRANSACTION` or `JOURNAL_ENTRY`.
</ResponseField>

<ResponseField name="target_id" type="string" required>
  Identifier of the record being adjusted.
</ResponseField>

<ResponseField name="adjustment_type" type="string" required>
  `REVERSAL` or `CORRECTION`.
</ResponseField>

<ResponseField name="reason" type="string" required>
  The maker's stated reason.
</ResponseField>

<ResponseField name="status" type="string" required>
  `PENDING_APPROVAL`, `APPLIED`, `REJECTED`, or `FAILED`.
</ResponseField>

<ResponseField name="requested_by" type="string" required>
  Identity of the submitting operator.
</ResponseField>

<ResponseField name="decided_by" type="string">
  Identity of the operator who decided. Present once a decision is made.
</ResponseField>

<ResponseField name="decision_reason" type="string">
  The checker's stated reason for their decision.
</ResponseField>

<ResponseField name="failure_reason" type="string">
  Populated if the request entered `FAILED` status.
</ResponseField>

<ResponseField name="reversal_transaction_id" type="string">
  Identifier of the reversal transaction created upon approval.
</ResponseField>

<ResponseField name="reversal_journal_entry_id" type="string">
  Identifier of the reversal journal entry created upon approval.
</ResponseField>

<ResponseField name="replacement_transaction_id" type="string">
  For `CORRECTION` requests: identifier of the replacement transaction.
</ResponseField>

<ResponseField name="replacement_journal_entry_id" type="string">
  For `CORRECTION` requests: identifier of the replacement journal entry.
</ResponseField>

<ResponseField name="created_at" type="string" required>
  ISO 8601 timestamp of submission.
</ResponseField>

<ResponseField name="decided_at" type="string">
  ISO 8601 timestamp when a decision was recorded.
</ResponseField>

<ResponseField name="applied_at" type="string">
  ISO 8601 timestamp when the adjustment was posted to the ledger.
</ResponseField>

## Approve a financial adjustment request

<Note>
  **Required permission:** `finance.approve` - Requires `Idempotency-Key` header. The approving operator must differ from the submitting operator.
</Note>

Approves a `PENDING_APPROVAL` adjustment request and atomically posts the reversal and, for corrections, the replacement entries. The original record is never modified.

```text
POST https://ledger.mavula.dev/api/financial-adjustment-requests/{requestId}/approve
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique adjustment request identifier.
</ParamField>

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.approve` permission. Must belong to a different operator than the maker.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this approval operation.
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier.
</ParamField>

### Request body

<ParamField body="reason" type="string">
  Optional reason for the approval. Max 500 chars.
</ParamField>

<CodeGroup>

```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/financial-adjustment-requests/adjreq_x5y4z3w2/approve \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 147598a5-10ee-49cc-b6e5-e5415bb65844" \
  -H "X-Correlation-ID: 5f8h3c2f-1j6g-9f43-3i2k-4h6f7g8i9j0e" \
  -d '{"reason": "Source documents verified, duplicate confirmed"}'
```

</CodeGroup>

### Response `201`

Returns the updated `FinancialAdjustmentRequest` with `status: "APPLIED"` and `applied_at` set. The `reversal_transaction_id` and `reversal_journal_entry_id` fields will be populated.

<Warning>
  A `403` is returned if the submitting operator attempts to approve their own request. Always use a distinct checker token.
</Warning>

## Reject a financial adjustment request

<Note>
  **Required permission:** `finance.approve` - Requires `Idempotency-Key` header. The rejecting operator must differ from the submitting operator.
</Note>

Rejects a `PENDING_APPROVAL` adjustment request. No financial entries are created. A `reason` is required.

```text
POST https://ledger.mavula.dev/api/financial-adjustment-requests/{requestId}/reject
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique adjustment request identifier.
</ParamField>

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.approve` permission.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this rejection operation.
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier.
</ParamField>

### Request body

<ParamField body="reason" type="string" required>
  Mandatory explanation for the rejection. Min 1 char, max 500 chars.
</ParamField>

<CodeGroup>

```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/financial-adjustment-requests/adjreq_x5y4z3w2/reject \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 258609b6-21ff-50dd-c7f6-f6526cc76955" \
  -H "X-Correlation-ID: 6g9i4d3g-2k7h-0g54-4j3l-5i7g8h9j0k1f" \
  -d '{"reason": "Supporting evidence is insufficient to proceed with reversal"}'
```

</CodeGroup>

### Response `201`

Returns the updated `FinancialAdjustmentRequest` with `status: "REJECTED"` and `decided_at` set.

## Error reference

| HTTP status | Meaning | Resolution |
| --- | --- | --- |
| `400` | Invalid request body or `Idempotency-Key` format | Validate all required fields; ensure debit/credit totals balance for corrections. |
| `403` | Missing permission or self-approval attempted | Use a distinct checker with `finance.approve`. |
| `404` | Request or target record not found in the tenant | Verify identifiers and tenant context. |
| `409` | State conflict or `Idempotency-Key` reused with different payload | Reuse the key only for identical retries; use a new key for modified payloads. |
