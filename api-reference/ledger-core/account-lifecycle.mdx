title: "Account Lifecycle API: Freeze, Unfreeze, Close"
sidebarTitle: "Account Lifecycle"
description: "Submit, approve, and reject account freeze, unfreeze, and close transitions through the MAVULA Ledger Core maker-checker lifecycle API."
---

The Account Lifecycle API controls how accounts move between the `ACTIVE`, `FROZEN`, and `CLOSED` states. No transition is applied immediately — every status change is submitted as a request by a maker and must be approved by a different operator acting as the checker. This two-step flow ensures that consequential account actions are always independently reviewed before they take effect.

<Note>
  **Maker-checker rule:** The principal who submits a lifecycle request (`finance.write`) and the principal who approves or rejects it (`finance.approve`) must be distinct. The API returns `403 Forbidden` if the same operator attempts both actions.
</Note>

---

## Submit an account status transition

<Note>
  **Required permission:** `finance.write` — Requires `Idempotency-Key` header.
</Note>

Submits a `FREEZE`, `UNFREEZE`, or `CLOSE` transition for the specified account. The request is created in `PENDING_APPROVAL` status and must be approved by a different operator before it takes effect.

```
POST https://ledger.mavula.dev/api/accounts/{accountId}/status-transitions
```

### Path parameters

<ParamField path="accountId" type="string" required>
  The unique identifier of the account to transition.
</ParamField>

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.write` permission.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this operation (16–128 chars, `[A-Za-z0-9._:-]+`).
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier. Recommended for log correlation.
</ParamField>

### Request body

<ParamField body="transition" type="string" required>
  The transition to apply. One of `FREEZE`, `UNFREEZE`, or `CLOSE`.
</ParamField>

<ParamField body="reason" type="string" required>
  Human-readable reason for the transition. Max 500 chars.
</ParamField>

<CodeGroup>
```bash Freeze
curl -sS -X POST https://ledger.mavula.dev/api/accounts/acct_a1b2c3d4/status-transitions \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f2b1e3a-4c2d-4d63-9b1a-2f7b6c0d5e91" \
  -H "X-Correlation-ID: 0f3c8d7a-6e1b-4a98-8d7f-9c1a2b3d4e5f" \
  -d '{"transition": "FREEZE", "reason": "Suspected unauthorized activity"}'
```

```bash Unfreeze
curl -sS -X POST https://ledger.mavula.dev/api/accounts/acct_a1b2c3d4/status-transitions \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 8c3d2f4b-5e6a-4f74-ac2b-3g8c7d1e6f02" \
  -H "X-Correlation-ID: 1a4d9e8b-7f2c-5b09-9e8g-0d2b3c4e5f6a" \
  -d '{"transition": "UNFREEZE", "reason": "Investigation concluded, no fraud found"}'
```

```bash Close
curl -sS -X POST https://ledger.mavula.dev/api/accounts/acct_a1b2c3d4/status-transitions \
  -H "Authorization: Bearer $MAKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 9d4e3g5c-6f7b-5g85-bd3c-4h9d8e2f7g03" \
  -H "X-Correlation-ID: 2b5e0f9c-8g3d-6c10-0f9h-1e3c4d5f6g7b" \
  -d '{"transition": "CLOSE", "reason": "Customer requested account closure"}'
```
</CodeGroup>

### Response `201`

Returns the newly created `AccountLifecycleRequest` with `status: "PENDING_APPROVAL"`.

```json
{
  "id": "lcreq_r9s8t7u6",
  "account_id": "acct_a1b2c3d4",
  "transition": "FREEZE",
  "from_status": "ACTIVE",
  "target_status": "FROZEN",
  "status": "PENDING_APPROVAL",
  "reason": "Suspected unauthorized activity",
  "requested_by": "operator_maker_01",
  "correlation_id": "0f3c8d7a-6e1b-4a98-8d7f-9c1a2b3d4e5f",
  "created_at": "2024-11-15T10:00:00.000Z"
}
```

## List account lifecycle requests

<Note>
  **Required permission:** `finance.read`
</Note>

Returns a cursor-paginated list of lifecycle requests. You can filter by account, status, or both.

```
GET https://ledger.mavula.dev/api/account-lifecycle-requests
```

### Query parameters

<ParamField query="account_id" type="string">
  Filter requests for a specific account.
</ParamField>

<ParamField query="status" type="string">
  Filter by request status. One of `PENDING_APPROVAL`, `APPLIED`, `REJECTED`, `FAILED`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor from a previous response's `next_cursor`.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results per page. Min `1`, max `100`, default `50`.
</ParamField>

<CodeGroup>
```bash List all pending requests
curl -sS 'https://ledger.mavula.dev/api/account-lifecycle-requests?status=PENDING_APPROVAL' \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```

```bash Filter by account
curl -sS 'https://ledger.mavula.dev/api/account-lifecycle-requests?account_id=acct_a1b2c3d4' \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```
</CodeGroup>

### Response `200`

<ResponseField name="items" type="array" required>
  Array of `AccountLifecycleRequest` objects. See [Submit a transition](#submit-an-account-status-transition) for field details.
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Opaque cursor for the next page. Absent when no further results exist.
</ResponseField>

## Read an account lifecycle request

<Note>
  **Required permission:** `finance.read`
</Note>

Returns a single lifecycle request by its identifier. Use this endpoint to poll for the outcome of a submitted transition after it has been reviewed.

```
GET https://ledger.mavula.dev/api/account-lifecycle-requests/{requestId}
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique lifecycle request identifier.
</ParamField>

<CodeGroup>
```bash cURL
curl -sS https://ledger.mavula.dev/api/account-lifecycle-requests/lcreq_r9s8t7u6 \
  -H "Authorization: Bearer $MAVULA_ACCESS_TOKEN"
```
</CodeGroup>

### Response `200`

<ResponseField name="id" type="string" required>
  Unique request identifier.
</ResponseField>

<ResponseField name="account_id" type="string" required>
  The account this request targets.
</ResponseField>

<ResponseField name="transition" type="string" required>
  The requested transition: `FREEZE`, `UNFREEZE`, or `CLOSE`.
</ResponseField>

<ResponseField name="from_status" type="string" required>
  The account's status at the time of submission.
</ResponseField>

<ResponseField name="target_status" type="string" required>
  The account status that will be set upon approval.
</ResponseField>

<ResponseField name="status" type="string" required>
  Current request status: `PENDING_APPROVAL`, `APPLIED`, `REJECTED`, or `FAILED`.
</ResponseField>

<ResponseField name="reason" type="string" required>
  The maker's stated reason for the transition.
</ResponseField>

<ResponseField name="requested_by" type="string" required>
  Identity of the submitting operator.
</ResponseField>

<ResponseField name="decided_by" type="string">
  Identity of the operator who approved or rejected. Present once a decision is made.
</ResponseField>

<ResponseField name="decision_reason" type="string">
  The checker's stated reason for their decision.
</ResponseField>

<ResponseField name="failure_reason" type="string">
  Populated if the request entered `FAILED` status due to an internal error.
</ResponseField>

<ResponseField name="correlation_id" type="string" required>
  Trace identifier for log correlation.
</ResponseField>

<ResponseField name="created_at" type="string" required>
  ISO 8601 timestamp when the request was submitted.
</ResponseField>

<ResponseField name="decided_at" type="string">
  ISO 8601 timestamp when a decision was recorded.
</ResponseField>

<ResponseField name="applied_at" type="string">
  ISO 8601 timestamp when the transition was applied to the account.
</ResponseField>

## Approve an account lifecycle request

<Note>
  **Required permission:** `finance.approve` — Requires `Idempotency-Key` header. The approving operator must differ from the submitting operator.
</Note>

Approves a `PENDING_APPROVAL` lifecycle request and applies the transition to the account. The account status changes atomically upon approval.

```
POST https://ledger.mavula.dev/api/account-lifecycle-requests/{requestId}/approve
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique lifecycle request identifier.
</ParamField>

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.approve` permission. Must belong to a different operator than the maker.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this approval operation.
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier.
</ParamField>

### Request body

<ParamField body="reason" type="string">
  Optional reason for the approval decision. Max 500 chars.
</ParamField>

<CodeGroup>
```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/account-lifecycle-requests/lcreq_r9s8t7u6/approve \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: a65e192f-aa5f-4dc9-a111-baf6136595a0" \
  -H "X-Correlation-ID: 3c6f1a0d-9h4e-7d21-1g0i-2f4d5e6g7h8c" \
  -d '{"reason": "Evidence reviewed and transition confirmed"}'
```
</CodeGroup>

### Response `201`

Returns the updated `AccountLifecycleRequest` with `status: "APPLIED"` and `applied_at` set.

<Warning>
  A `403` is returned if the same operator who submitted the request attempts to approve it. Always use a distinct checker token.
</Warning>

## Reject an account lifecycle request

<Note>
  **Required permission:** `finance.approve` — Requires `Idempotency-Key` header. The rejecting operator must differ from the submitting operator.
</Note>

Rejects a `PENDING_APPROVAL` lifecycle request. The account status remains unchanged. A `reason` is required when rejecting.

```
POST https://ledger.mavula.dev/api/account-lifecycle-requests/{requestId}/reject
```

### Path parameters

<ParamField path="requestId" type="string" required>
  The unique lifecycle request identifier.
</ParamField>

### Request headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` with `finance.approve` permission.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique, stable key for this rejection operation.
</ParamField>

<ParamField header="X-Correlation-ID" type="string">
  Optional trace identifier.
</ParamField>

### Request body

<ParamField body="reason" type="string" required>
  Mandatory explanation for the rejection. Min 1 char, max 500 chars.
</ParamField>

<CodeGroup>
```bash cURL
curl -sS -X POST https://ledger.mavula.dev/api/account-lifecycle-requests/lcreq_r9s8t7u6/reject \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: b76f203g-bb6g-5ed0-b222-cbg7247606b1" \
  -H "X-Correlation-ID: 4d7g2b1e-0i5f-8e32-2h1j-3g5e6f7h8i9d" \
  -d '{"reason": "Supporting evidence is insufficient to justify account freeze"}'
```
</CodeGroup>

### Response `201`

Returns the updated `AccountLifecycleRequest` with `status: "REJECTED"` and `decided_at` set.

## Error reference

| HTTP status | Meaning | Resolution |
|---|---|---|
| `400` | Invalid transition or malformed request body | Validate `transition` value and ensure `reason` is present. |
| `403` | Missing permission or self-approval attempted | Use a distinct checker with `finance.approve`; ensure maker and checker differ. |
| `404` | Account or request not found in the tenant | Verify identifiers and tenant context. |
| `409` | State conflict or `Idempotency-Key` reuse with different payload | Reuse the key only for an identical retry; refresh current state before resubmitting. |
